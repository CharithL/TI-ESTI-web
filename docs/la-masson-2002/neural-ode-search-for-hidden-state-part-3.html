30How the new model finds biological architecture

A trial-and-error loop that scores each architecture against 160 biological variables and uses the pattern of misses to choose the next one.

CHARITH’S QUESTION — 30“So how does this new model work? How does it find any biological architecture?”
Claude’s answer · Claude Opus 4.6

How DESCARTES-NeuralODE Works — Simply

Think of it as a smart trial-and-error system that learns from each failure.

The Loop

1. Pick an architecture (simplest first)
         ↓
2. Quick test: can it learn 50 timesteps? 
         ↓ NO → skip, record WHY it failed
         ↓ YES
3. Full training on 2000 timesteps
         ↓
4. Score: which of 160 biological variables 
   did the model's hidden states match?
         ↓
5. Record what it GOT and what it MISSED
         ↓
6. Analyze ALL failures so far → find patterns
         ↓
7. Use patterns to pick/generate next architecture
         ↓
   Back to step 1

The Key Difference From Normal Neural Architecture Search

Normal NAS asks: "which architecture gets lowest loss?" — one number.

DESCARTES asks: "which of 160 biological variables did each architecture recover, and WHY did it miss the others?" — a structured profile.

Concrete Example

Iteration 1: Volterra recovers 89/160 variables. Mostly gets tc_mT (T-current activation) but misses nrt_V (nRt voltages). Pattern: kernel models can't capture recurrent feedback.

Iteration 2: LSTM recovers 20/160. Gets some synaptic variables but misses gating variables. Pattern: discrete gates don't match continuous gating dynamics.

Iteration 3: Standard Neural ODE recovers 0/160. Fails completely — vanishing gradients. Pattern: adjoint method + 2000 steps = dead gradients.

DreamCoder analyzes all three failures: - "nRt voltage variables missed by ALL architectures → need explicit oscillatory structure" - "Slow-timescale variables missed by everything except Volterra → need multi-timescale dynamics" - "ODE family exhausted with adjoint gradients → try segmented gradients"

Gap compass says: 71% of missing variables are nRt_state category, mostly slow-timescale. Direction: need oscillatory + hierarchical timescale architecture.

Balloon expansion generates: A new template — Coupled Oscillatory RNN with segmented gradients and hierarchical latent space. This architecture specifically targets the gap.

Why It Can Find Biological Architecture

It doesn't know biology. It knows which 160 numbers the model's hidden states should correlate with. The biological ground truth (m_T, h_T, nRt voltages, GABA conductances) comes from your simulation — you recorded every internal variable when running the real Hodgkin-Huxley circuit.

So the system is essentially asking: "does hidden unit #37 in my Neural ODE track the same trajectory as T-current inactivation gate h_T in biological neuron #12?"

If yes → that variable is "recovered." If no architecture recovers it → the gap analysis asks what property of h_T (slow timescale? oscillatory? bounded 0-1?) suggests what architectural feature might help.

The biology isn't discovered from nothing. It's discovered by matching learned representations against known biological measurements and systematically closing the gap.

Interesting idea — but the bottleneck is different here than in trading strategies. Let me explain why, and what WOULD work.

Why It Works for Trading Strategies

Explorer-agent generates ~1000 strategies/day. That's enough data to train a transformer that learns "what makes a strategy survive the 7 gates." Cheap to generate, cheap to evaluate.

Why It Doesn't Directly Work Here

Each architecture evaluation takes 1-4 hours on GPU. To train a transformer meta-learner you'd need hundreds of evaluations. At 2 hours each, that's 200+ GPU-hours before the meta-learner has enough data to be useful. You'd find the answer by brute force before the meta-learner learns anything.

What WOULD Work: A Surrogate Meta-Learner

Instead of a full transformer, use a lightweight predictor trained on cheap features:

Input:  architecture config (6 properties) + 
        short-segment results (50-step, takes 60 seconds)

Output: predicted 160-dim recovery vector

The workflow becomes:

1. Run 8-10 real evaluations (your current DESCARTES loop)
2. Train small predictor on those results
3. Use predictor to score 1000s of candidate architectures instantly
4. Only run full training on top-5 predicted candidates
5. Add real results back to predictor training set
6. Repeat

This is essentially Bayesian optimization with a neural surrogate — standard in NAS literature (BOHB, BANANAS).

The Deeper Version That IS Novel

Where a transformer meta-learner becomes genuinely interesting for your work is at a different level — not choosing architectures, but learning the mapping from architectural features to biological variable recovery across multiple neural circuits:

Train on: TC-nRt circuit results (your current data)
          + Chennu propofol EEG results (your next dataset)
          + van Blooijs CCEP results (dataset after that)
          + hippocampal CA3→CA1 results (fourth dataset)

Transformer input:  (circuit_type, architecture_config, 
                     input_output_description)
Transformer output: predicted biological variable recovery pattern

THAT would be a genuine "consciousness architecture foundation model" — a meta-learner that predicts which computational structures recover which biological mechanisms, generalizing across brain circuits. After training on 4-5 circuits × 8-10 architectures each, it could predict recovery patterns for circuits it hasn't seen.

But that's Paper 3 or 4 territory. Right now, the immediate priority is getting real A-R2 data into the DESCARTES pipeline and running the 8 templates on actual thalamic data. The surrogate predictor becomes useful after you have ~10 real evaluations to learn from.

32Explained more simply

Biology is “rate of change depends on current state”, and so is a Neural ODE: the container is the right shape; training has to fill it.

CHARITH’S QUESTION — 32“Explain this more simply.”
Claude’s answer · Claude Opus 4.6

The Simple Version

Biology says: "This thing changes over time depending on what it currently is."

That's literally what a differential equation means. dV/dt = f(V) just says "how fast voltage changes depends on current voltage."

Every biological variable in your circuit follows this pattern:

  • Membrane voltage changes depending on what channels are open
  • Channel gates open/close depending on current voltage
  • Synaptic conductance rises/falls depending on whether a spike arrived

It's all "the rate of change depends on the current state."

A Neural ODE says the exact same thing:

"I have hidden states z. They change over time: dz/dt = f(z). I'll learn f from data."

The punchline:

If the Neural ODE learns the right f, its hidden states z could literally become the biological variables — voltage, gating, conductance. The container is the right shape. The question is whether training fills it with the right contents.

That's why Volterra recovering 89/160 bio variables is surprising — it's NOT an ODE, it's a kernel filter. It got the right answers with the wrong container. And why the Neural ODE recovering 0/160 is frustrating — it has the right container but training (gradient descent through 2000 steps) couldn't fill it. The DESCARTES framework is about finding a way to fill the right container.

33Is this related to hidden Markov states?

Yes conceptually — hidden causes inferred from outputs — but HMM states are discrete and biological gating is continuous.

CHARITH’S QUESTION — 33“So are hidden Markov states related to this? Yes or no.”
Claude’s answer · Claude Opus 4.6

Yes, conceptually. Both have hidden states you can't directly observe but must infer from outputs.

The difference: HMM hidden states are discrete (state A → state B with probability 0.7). Biological gating variables are continuous (m_T smoothly moves from 0.2 to 0.8). Neural ODEs have continuous hidden states too — which is why they're the better match for biology.

But the core idea is the same: something you can't see is driving what you CAN see, and you're trying to recover what that hidden thing is.

        model="claude-sonnet-4-20250514",
        max_tokens=500,
        messages=[{"role": "user", "content": prompt}]
    )

    config = json.loads(response.content[0].text)

    return ArchitectureTemplate(
        id=f"llm_generated_{self.balloon_expansions}",
        name=config["name"],
        description=config["reasoning"],
        family=f"llm_{self.balloon_expansions}",
        time_handling=TimeHandling(config["time_handling"]),
        # ... map the rest
    )

9 = the number of pre-defined architecture templates (T0 through T8). That's it.

But with LLM in the loop, there's no fixed number. The LLM generates NEW templates after exhausting the pre-defined ones. So the stopping condition becomes:

Stop when: 1. Target recovery achieved (e.g., 120/160 bio vars) → success 2. GPU budget exhausted (e.g., 24 hours) → practical limit 3. With the LLM, iterations could be 9, 15, or 30 — driven by results, not a hardcoded list.

43Feeding the working templates back to the LLM

That is DreamCoder's sleep phase: a growing prompt of what worked, what failed and what is still missing turns the LLM into a reasoning layer on the history.

CHARITH’S QUESTION — 43“Let's say the LLM gives templates T1, T2, etc. What if we use these outputs to feed the LLM the direction of the working templates — like DreamCoder's output?”
Claude’s answer · Claude Opus 4.6

Yes — that's exactly what DreamCoder's sleep phase is. You're describing the full loop:

Iteration 1: LLM suggests T_llm_1 → trains → 25/160 recovered
Iteration 2: LLM suggests T_llm_2 → trains → 40/160 recovered  
Iteration 3: LLM suggests T_llm_3 → trains → 15/160 (worse!)

DreamCoder analyzes ALL three:
  "T_llm_2 worked best. It used LTC + segmented gradients.
   T_llm_2 recovered nrt_state that T_llm_1 missed.
   T_llm_3 used oscillatory but LOST tc_gating that T_llm_1 had.
   Pattern: LTC helps nrt, but oscillatory hurts tc_gating."

Feed THIS back to LLM:
  "Combine LTC (good for nrt) with biophysical latents 
   (good for tc_gating). Avoid pure oscillatory."

Iteration 4: LLM suggests T_llm_4 → trains → 55/160 ← best yet!

The prompt grows each iteration:

prompt = f"""
WHAT WORKED (keep these features):
- LTC time handling → recovered nrt_state (40/60)
- Segmented gradients → enabled training convergence
- Biophysical latents → recovered tc_gating (50/60)

WHAT FAILED (avoid these):
- Adjoint gradients → zero learning (3 attempts)
- Pure oscillatory → lost tc_gating every time
- Standard ODE solver → too slow, budget exhausted

WHAT'S STILL MISSING:
- synaptic variables (35/40 still missing)
- Pattern: all missing synaptic vars are GABA_B (slow)
- GABA_A recovered but GABA_B never recovered by any model

COMBINE the working features and target the gap.
"""

This is accumulating knowledge across iterations. Each run adds to the prompt. The LLM doesn't just see the gap — it sees the trajectory of what's been tried and what each feature contributed.

That's the difference between: - Static gap compass: "synaptic missing → add multiplicative coupling" (same suggestion every time) - LLM with DreamCoder history: "multiplicative coupling was tried in T_llm_2 and didn't help synaptic. But T_llm_2 also used euler solver which is too coarse for slow GABA_B dynamics. Try multiplicative coupling + implicit_adams solver this time."

The LLM becomes a reasoning layer on top of DreamCoder patterns. DreamCoder extracts the structured data. The LLM interprets it and generates the next hypothesis. Each iteration makes the LLM smarter about THIS specific problem.

44So no meta-learner is needed?

Right. The LLM is the meta-learner. It just doesn't need training.

Transformer Meta-Learner LLM in Loop

For now: LLM + DreamCoder history = meta-learner for free.
